## 数字意味着什么

Archify 正确交付3/4题。退货题三次都被原生 finalize 拒绝：前两次 `drop` 路由与端点方向冲突，第三次显式路由交叉。失败零分拉低四题均值。其余三题内容全对；新增两次修复未提高整组总分，反而增加耗时与调用。这是当前模型与当前 host 下真实暴露的交付问题。

Mermaid 四题内容、布局均为100，但退货题“修改标签后重载”的探针无法可靠识别变长标签，导致可编辑性未确认、效率奖励与总分缺测。这不等于 Mermaid 内容有错。SVG 库存题的 charge 标签可能遮挡；HTML 退货题 damaged 标签可能遮挡、eligible／arrived 归属不明确，观察器不能可靠确认，因此这两组总分也缺测。

Next AI Draw.io MCP 四题结构内容全对。不过实际导出 SVG 有自适应暗色样式，当前白底 host 中部分箭头对比度低；当前布局分未衡量对比度，**99.9不能解释为视觉质量最好**。Excalidraw MCP 四题交付，但仅两题内容完全正确；箭头连接错误降低内容分，且内容未全对的两题没有效率奖励。

速度／成本的满分锚点会饱和。费用很低时 K=100 不表示方法成本相同；内容或可编辑性不合格也可能令效率奖励为零。应同时看真实用量。

## 公平性与边界

- 题目固定为 architecture-01、workflow-01、architecture-04、workflow-04；公开开发／校准题、临时人工金标准，各格一次试验，不能推出总体显著性结论。
- 同一个官方 deepseek-flash，temperature0.2、thinking disabled、每次输出8192上限。每格3候选、600秒、200,000实际输入输出tokens、USD0.25上限。修复、失败及全部文档计入 usage。
- Archify 使用当前完整 Skill／默认项／schema／示例／交付文档，Architecture v1、Workflow v2，真实执行 finalize showcase。没有沿用旧 pilot 的强制 workflow v1。
- 六组共用“完整文档预加载 → 原生源码提交 → 真实诊断 → 最多两次修复”的 host；没有人工修图、手改模型源码、按结果调权重或选择性重跑。它不是未修改的 Codex／OpenCode agent，也不是各产品默认 AI 应用。
- Next AI Draw.io MCP 实际运行原生 create_new_diagram/export_diagram，并用原生 mxCodec 核对提交与导出图结构，避免旧画布误报成功。项目36,341 stars，源码6cc5cd7925777a141e4b278d0017dfbcc8cdfef2，MCP0.4.6／draw.io32.0.2。

- 原生样式保留。可见节点／方向／文字独立观测；临时副本执行改名、重载验证可编辑性。其覆盖有限，缺测如实保留；对比度也是已确认的计分盲点。
- 首稿仅记第一次调用；最终包含所有调用及中间诊断等待。最终交付后的离线验收不计速度。旧“首轮成功”字段不会把修复后成功伪称首稿成功。

## 开发过程、验证与清理

前两轮开发实跑因原生图形覆盖不足、draw.io 成功 ACK 却导出旧画布而作废，均保留，不进入本轮排名。共82次已返回 usage 的调用，已知费用小计USD0.143264052；另一次传输错误 usage／费用未知，不按零记。两次事前费率窗口检查中止未发API请求。当前有效轮按每次实际 dispatch 选择分时费率，48个响应ID与远端实际请求逐一一致。

165项 benchmark 检查全部通过、无跳过；核心19项通过。真实浏览器验证6行、24格、23张图／匿名评分项，所有下载链接有效，390px页面无横向溢出。调用 usage、缓存拆分、源码／产物hash、冻结评分重算均通过。复核发现的“回退较早候选应计入最后选择时间”已修复后续 harness；本轮没有出现保留较早候选的情况，冻结证据未改。

临时浏览器／编辑副本和远端任务 helper 清理；原始实验、作废轮及隔离运行时留作复核。用户 `.env` 保持不变，密钥始终只在 mac-studio 使用。没有 PR。
