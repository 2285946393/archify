# Archify benchmark v2 设计

日期：2026-10-21。基线：dev `e49cfd2aff5bc9839332367b5b12c862a97c08ac`。状态：设计提案；证据与方法审计见 [审计报告](../../benchmarks/2026-10-21-benchmark-audit.md)。

## 目的与成功条件

评估 AI 能否在给定预算内，准确、清楚地把需求变成可编辑结构图，以及 Archify 相比直接写 Mermaid / SVG / HTML、同类工具和相关论文方法的效果。测量节点与关系正确性、遮挡与可读性、生成时间、实际 token 成本，并增加可选的人类审美评估。

保留低成本、确定性的子轨，使 autodev 能无人值守优化。自动优化的分数只依赖已验证的客观结果；缺失人评既不扣分，也不补零、插值或调整自动分数权重。没有人评时只报告客观表现，不宣称“更美”。

本设计不把所有指标塞进一个通用加权总榜。一次 autodev 优化仍严格使用一个预先固定的数值目标；其他必要能力通过 guard 验证，失败使候选无效，不能用节省 token 补偿错误输出。

## 用户要求与本方案选择

用户要求：重新核查非生图类顶会方法；解释指标作用；补充消融；保留 autoresearch/autodev 自动循环；增加 optional 人评；比较直接写图、论文方法以及至少 1k stars 的同类项目。

本方案选择：延续 Node.js、CLI、JSON/JSONL 和现有外部 Agent runner；不引入 provider SDK 或更换 v1 判定语义。首轮主要工具对照选 Next AI Draw.io、官方 draw.io MCP 和官方 Excalidraw MCP；D2 与 Diagrams 在适用子集扩展。研究方案和 benchmark 实现是两阶段，优化产品又是之后的独立阶段。

## 四个互补轨道

| 轨道 | 研究问题 | 输入与评估 | 使用频率 |
| --- | --- | --- | --- |
| diagnostic-replay | 反馈是否精确、足够、可执行，是否误拒合法输入 | 合成错误 + 合法边界；rules / oracle / 字段干预；独立错误身份和语义保留检查 | 每次相关变更，可接 autodev |
| frozen-render | 同一内容换 renderer / 路由后是否更清楚、更快 | 冻结的完整内容与意图；原样跨版本回放；统一 SVG/DOM 几何观测 | 布局、检查器和性能优化 |
| agent-generation | 真实 AI 在相同任务下是否更容易完成 | 自然语言需求或固定仓库源码；独立会话；同一模型/Agent 的工具对照；外部语义与产物检查 | 候选进入验证阶段后运行，不在每次小改动时全跑 |
| human-review | 读者是否更容易理解、更愿意使用输出 | 可选盲评、配对偏好和分项量表；固定图与展示条件 | 阶段性校准与最终报告 |

复用 `repair-rounds`、`ordinary-model-floor` 和 `real-repo-generation` 的现有能力。v2 负责共同运行记录、格式适配、可比较指标与消融，不再创建另一份需要维护的产品 validator。

## 对照组与公平性

### 同一 Agent 的工具对照

以同一 Agent、模型版本、推理配置、工具权限、任务、预算和隔离规则，比较 Archify、直接 Mermaid、直接 SVG / HTML，以及同类 MCP / DSL。模型可以自然使用当前工具的编译、预览与修复能力，这些能力属于工具的真实价值，使用次数、成本和返回的图像 token 全部计入。

预先固定每个工具的规范文档包和格式要求，禁止人为把竞争工具设成“不能预览或修复”的弱基线。文档长度可以不同，这是实际学习成本；不人为填充到同样 token。不得向任一 Agent 暴露金标准、评分规则内部实现、参考布局、其他工具输出或当前优化假说。

固定共同任务，不在任务正文写“Use Archify”；工具特有的说明由 arm 配置注入。开发集任务按复杂度与图型分层；公开产品比较使用预先声明的共同支持子集，同时单独列能力覆盖。选择性不支持与生成失败分开，不能事后把失败改为 N/A，也不把原生图型更多当成单题质量更高。

### 学术系统对照

DiagramAgent 的 Plan / Code / Check 分工可用于可复现的同模型 scaffold 变体，但只能标“依论文重实现”，不能标官方系统复现。其官方仓库没有完整可运行的 Agent pipeline。OmniDiagram 可按作者公开模型运行，列单独的系统级比较，固定其模型、权重版本与推理设置；模型不同的结果不能归因于工具。

首轮实际比较只运行可用实现。安装或复现失败保留原因，不根据论文表格填入本实验结果。项目 stars 只作入选快照；代码、模型、文档、布局引擎和字体版本必须在运行前固定到 commit/digest。

## 语料设计

先建立 30 个有独立金标准的 bounded 任务：沿用首版 5 种图型，每种 3 个复杂度、每档 2 题。以任务族为单位固定 15 题开发集、5 题校准集、10 题保留集；同一个基础图的改写、缺陷变体和语义等价版本不得跨集合。

复杂度至少记录节点数、边数、分叉、循环、嵌套、标签长度和跨边界关系；不只按节点数分 easy/hard。取材包括有依据的需求说明和可控合成结构，验证器都用人工核定的事实，不能把某模型生成的参考图直接视为真值。

其余 `erd/class/tree/timeline/waterfall` 每种先放两个完整内容用例于扩展集，不与 30 题核心分数混合，直到完成语义适配与金标准验证。ERD 要验证列、PK/FK 和基数；sequence 要验证事件顺序；timeline/waterfall 要验证时间、数量和单位，不能硬塞成无类型图 F1。

真实仓库轨复用已固定的 5 个项目和 prompt 范围，增加工具中立措辞；金标准要由独立读码者确认节点、方向、条件和源码证据。在首轮尚未建立完此金标准时，只能作审查对照，不能自动获得“客观语义正确”。

保留集只在独立评估环境运行，优化 Agent 不能读取题目与答案；仅有文件 hash 冻结不能防止针对答案过拟合。开发集优化完成后冻结候选，再用保留集验证，不能反复把保留集结果反馈回同一优化循环。

## 自动指标与适用决策

| 核心指标 | 定义 | 目的与使用限制 |
| --- | --- | --- |
| objectiveSuccess@budget | 全部计划任务中，同时满足明确内容要求、可交付、指定几何护栏且未超预算的比例 | 端到端主结果；失败、超时、无产物保留在分母；不包含主观审美 |
| 节点 precision / recall / F1 | 对冻结语义 key、别名与类型作一对一匹配；重复生成不能多次命中 | 区分漏节点与乱加节点；必需节点遗漏仍使任务失败，F1 用于解释 |
| 直接关系 precision / recall / F1 | 匹配有向端点、关系标签/条件/类型；区分不存在的边与错方向 | 防止节点全对但关系错误；可达性只作附属指标，不能掩盖缺失中间节点或直接边 |
| 必需约束保持 | 必需 label/数值/条件/分组和编辑后不该改变的部分逐项验证 | 拒绝靠截断必要文字、删边删点或改需求来降低 overlap 与成本 |
| geometricDefectFree | 在固定 CSS viewport、字体、缩放、导出规则下，没有预先定义的严重遮挡/裁切 | 底线指标；不等同主观美观，不拿 Archify 自己的 gate 作唯一外部裁判 |
| timeToObjectiveSuccess | dispatch 到首个后来通过离线确定性验收的候选的提交时刻；另报验收完成和最终响应时刻 | 候选就绪速度，不含离线 grader 时长；timeout 视为删失/失败，不能从耗时分布丢掉；还报告完整预算下成功率 |
| measuredTokens / measuredCost | 来自全部模型调用 usage 的实际累计；明确输入、输出、缓存与推理口径 | 成本主量；不把词法估计当账单，不把会话只读文档一次的假设当观测 |
| MRR | 全题均值 `success_i / k_i`，`k` 为首稿提交在内的候选检查轮；预算内未成功贡献 0 | 在固定检查成本和范围下评价修复效率；不替代真实时间，也不把一次会话等同首稿 |

首稿成功率、总修复轮数、每题总回执 bytes、词法单位、检查器误报率、诊断归因和建议执行率属于解释项；避免把高度相关的字段重复加权。对新 metric，先写清它会改变哪项工程决策、成本和可被操纵方式；没有具体用途就不进入主报告。

### 独立语义检查

金标准保存事实与允许的等价表达，而不是参考坐标。语义 key 用固定别名、实体类型与一对一最大匹配；有歧义或需要未审定的模型判断时记 `unverified`，不能由生成者自报 passed。

Archify JSON、Mermaid、draw.io XML、Excalidraw scene 分别解析到公共语义表示和最终可见几何；普通 SVG/HTML 优先使用真实可见文本、分组和已验证的端点关系。自由 SVG 关系若无法确定性解析，就由独立标注建立对应或记 unknown，绝不为了补评分而相信生成者写的隐藏 metadata。某后端无法取得完整客观语义时不加入 objective 总排名，但仍可参与渲染、时间与人评轨。

必须检查原生源里有的元素是否真正显示出来，包括零透明度、遮挡、超画布、隐藏 DOM、与画出来不一致的 metadata。语义表示和截图之间的对应关系有可核查证据；更好看的图不能掩盖缺事实。

### 可编辑交付的最低标准

首个切片把“可编辑”限定为结构化源可重新加载和局部修改，不要求内置 GUI 或让 AI 再编辑一轮。必须交付原生源：Archify JSON、Mermaid 文本、draw.io XML、Excalidraw scene，或保留可见文字、独立图形和关系元素的 SVG/HTML。只有位图、把整张图转成无法对应语义对象的路径，或在 HTML 中嵌一张截图都不合格。

adapter 在副本上重新加载、改一个指定标签并重渲染，验证该标签变化而不丢节点、关系与其他必需文字；此能力检查由外部 evaluator 完成，不改变冻结的 Agent 输出，也不计为其 repair round。源可编辑但端点无法可靠提取时保留 editability 结果，objective semantics 仍记 unverified。自然语言编辑任务放在后续单独轨道，不能与首稿生成混计。

### 几何观测

初始 viewport 统一 1440×900、zoom=100%、DPR=1、同字体与静止主题，附完整画布图；同题两边使用同一种显示缩放策略，不能仅对某工具自动 fit。原生默认样式另留一份，不把它替换成更有利的统一截图。

记录 node-node 意外重叠、label-label 重叠、label-node 越界、非关联 edge-node 穿过、被裁切对象及图外文本的数量和严重度。节点重叠严重度用相交面积除较小对象面积；合法父子包含、共享端口、连接节点的边和有意公共干线必须明确排除。label 应使用最终浏览器测量的字形/文本框，而非字符数估算。

边交叉、拐弯、绕行与留白先作诊断项。预先声明真正有损可读性的交叉、重叠和裁切护栏；更少拐弯或更少留白不自动意味着更好。绝对数量与按图规模归一化的数值都保留。大小、方向和特殊图型要在分层结果里解释，不能用放大画布或删除标签制造几何改善。

首个切片实现可版本化的 profile，不让各 adapter 自行定义通过阈值。试点暂定 `desktop-single-page-v1`：将内容按相同的等比 contain 规则放在 1440×900 viewport 的 1280×720 评估区；关键文字以最终变换后的有效字号至少 12 CSS px 为候选门槛。节点/文字意外相交或必要内容被裁切，两轴侵入均超过 0.5 CSS px 的容差时失败；非关联边穿过节点内部也失败。有意包含与合法关系接触依任务语义排除，边交叉数量本身不作硬门槛。工具原生默认截图仍保留，不能拿规范展示图替代真实默认呈现。

12px 和 0.5px 是本方案的试点选择，不冒充论文结论或通用美观标准。先在独立合法样例、已知遮挡样例和缩字干预上校准，同时报告 10/12/14px 的敏感性；未完成校准的结果只标 pilot，不用于正式排名或 autodev keep。校准后在测 baseline 前冻结 profile。高密度整图、允许滚动的任务另建 profile 分层报告，不因难放进一屏就悄悄删节点或只比较裁切视窗。

### 时间和 token

保存首稿前、修复、最终交付三段成本；总 wall time 与并行工具/子会话工作总量分开，重叠时长不能相加成端到端耗时。编译、浏览器、工具启动、模型调用和可观测队列分别计时；setup、下载与冷启动单独标记，cold/warm 不能混算。

每条 usage 记录调用 id、provider、精确 model、usage schema、input/output、cached input、reasoning、图片相关口径及是否已包含于总数。缺失字段为 null 并标来源，推理 token 已包含在 output 时不得再加一次。所有子 Agent 调用、失败调用和重试都计入。美元成本需记录 provider 价格快照和各类计费规则；拿不到完整账单时只报告可观测部分。

不将这些研究探针的 lexical units 重命名成真实 tokens。开发机上 rules / oracle 的 CLI 测量也不能当成模型生成速度。

外部金标准与最终 grader 不向生成 Agent 返回反馈，防止不同 adapter 提供额外解题能力。工具原生的编译/诊断/预览反馈可以使用，其等待与处理时间属于生成过程。运行记录分别保存 `candidateSubmittedAt`、`verificationStartedAt`、`verificationCompletedAt`；离线确定哪个候选首个合格后，用其提交时间计算 timeToObjectiveSuccess。若某候选必须靠事后人工标注才知道语义是否正确，该项客观时间为 null，仅报告 artifact-ready 时间及单独的人评结果，不能回填“自动成功时间”。

## Optional 人工评估

默认 `human.status = not_requested`。人工介入可以在客观运行结束后异步补交，使用 artifact hash、固定图、任务 id、rubric 版本与 pseudonymous reviewer id 绑定。对象变化后旧评分不可沿用。明确 `requested/in_progress/completed/partial/skipped`，缺评不是 0 分。

盲评隐藏模型与工具名称、成本和自动分数；任务描述与同样展示条件可见。A/B 左右顺序随机，保留 seed，允许平局和“两者都不可用”。绘图风格可能泄露工具，需承认这项不可完全消除的偏差。

| 评分项 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 阅读与追踪 | 主要路线或文字难以辨识 | 能完成任务，但需要反复定位 | 关键路径、方向和标签一眼可追踪 |
| 层级与分组 | 分组和主次混乱 | 主要分组清楚，局部层次弱 | 层级和边界自然支持理解 |
| 排版与视觉平衡 | 拥挤、失衡或大片无用空白 | 整体可用，仍有局部拥挤/松散 | 间距、对齐与密度适合该题 |
| 风格与视觉区分 | 字体/色彩不一致或对比不足 | 基本一致，可区分主要角色 | 一致且角色/状态区分清楚 |
| 整体审美偏好 | 明显不愿采用 | 可接受 | 愿意直接使用或分享 |

语义正确性单独给 `correct/incorrect/unverified` 和证据，不与审美混成一项。没有可读产物的运行列为交付失败，人评审美 N/A；同时报告各 arm 的评分覆盖和失败率，禁止只展示好看的成功子集。

首轮每个配对至少两位独立评审，对关键分歧引入第三位；单人作者自评可保存但标为非独立。记录每人原始分数、分歧与批次，报告任务级配对 win/tie/loss 和分项中位数；样本足够时报告 ordinal Krippendorff alpha 与按任务聚类的 bootstrap 区间。量表没有足够区分度或一致性时先修订 rubric，再建立新版本，不调分讨好自动结果。

这些分数始终位于报告的 human 部分，不改变 `objectiveScore`，也不触发 autodev attempt 的 keep/rollback。需要宣布视觉改进时再要求完成相应盲评；缺评只阻止视觉结论，不阻止客观优化运行。

## 两类消融实验

### 指标有效性

先建立预期方向明确的受控干预对：删除必需节点、反转关键边、删条件、截短必需 label、隐藏节点、缩小字体、增加无关装饰、只换配色和等价布局。正确的语义指标必须拒绝前几类，等价布局不应被误判；几何指标对真正遮挡敏感，但不奖励内容删减。

去掉语义、独立可见性或合法输入检查，观察错误候选是否变成“更优”；固定已保存产物，逐项去掉旧加权分数的分量，报告排序变化和失真的候选。这是评分规则敏感性实验，不是优化组件的因果消融。

用可选人评检查几何代理能否预测实际读图与偏好，按任务进行交叉验证，不能在同一批样本上反复调权并报告泛化结论。相关性支持代理价值，但不能证明因果；没有人评数据就把“几何更好”限定成已测缺陷更少。

### 组件与反馈机制

1. 重放反馈：full、去 subject、去 evidence、去 supportedFixes、去 message；规则与真实 Agent 分开，记录修复成功、信息保留、轮数和实际成本。当前六题机制试验已执行，见审计；真实 Agent 版本尚未运行。
2. 工具机制：完整工具、仅编译反馈、加结构化反馈、加浏览器视觉反馈。每个工具只关闭其有的能力，不伪造不存在的能力；完整模式是主对照，简化模式只用于解释。
3. 优化机制：对 r5 的候选排序、update 降噪、schema 文案去重各做基线 + 单项 + 全量，以及全量减单项；诊断字段的真实值与建议完整性都作护栏。历史顺序改进不足以估计独立贡献；存在互作用时使用预先选定的 2×2 或 2³ 设计。
4. 跨 workload 验证：开发题上的改进在独立保留题和新图规模上是否仍成立；匹配无缺陷合法输入，检查误拒率而非只测非法输入。

每次真实 Agent 比较用相同题、重复编号与模型配置，顺序交替，环境独立。阶段一试点以至少三次独立重复估计波动，不能把这个数字当统计功效充分；正式样本数由试点方差与预先定义的最小有用差异确定。保留全部失败，不能只复跑失败 arm 直到胜出。

## 接入 autodev 的目标

遵循 [autodev optimization 契约](https://github.com/Momoyeyu/autodev/blob/master/autodev/references/clarify-optimization.md)：一轮一个数值目标或固定加权和，先固定 workload、单位、方向、噪声、改进阈值、时限和冻结文件，再记录 baseline。benchmark 本身改动与被 benchmark 优化的产品改动分开。

优先采用有明确含义的目标，而不是恢复旧总分：诊断优化可用全样本语义受约束的 MRR；纯回执瘦身可用总回执 bytes / lexical units，前提是回执语义、建议执行和修复结果不退化；性能优化可用同输入 median 工具延迟，前提是内容、产物和几何护栏相同。

输出一个有限 score；guard 不通过返回非零/invalid，不输出可供保留的“罚分后成绩”。验证不齐或运行失败属于测量失败，不能以 0 或漏题方式改变分母。人评分数和缺失状态均不参与 score。保留原始分量、预算、环境、源码与输入 hash、attempt route 和所有拒绝记录。

真实 Agent token/时间昂贵且有波动，不默认放入每次本地 autoresearch 循环。先用便宜代理找候选，再用独立真实会话验证；只有代理在开发集上已建立有效性并保持 held-out 检查时，才能声称它适合该优化目标。

## 共同运行记录与兼容性

新增 v2 run 记录而不是改变 v1 `firstPassUsable`：其历史含义仍是一次完整 Agent invocation 后经审查可用，不是首稿成功。

v2 记录至少包含：schemaVersion、runId、suite/manifest/evaluator hash、taskFamily/split、source evidence、arm/工具/模型/Agent 与版本、预算与环境、输入 prompt hash、按顺序的 candidate/artifact hashes、工具事件、usage、firstDraft、delivery、objective、human 和 unknownReasons。外部 runner 负责调度与保存会话，harness 独立验收；provider 凭据不进入仓库。

字段中 `coverageComplete`、`objectiveVerified`、`humanReviewed` 分别存在；不能用一个 `evidenceEligible` 同时暗指矩阵完整、真值可靠与人工通过。对照报告拒绝混合 manifest/evaluator hash、预算、模型配置或重复 runId；未知版本、无候选、部分 usage 和非共同支持能力都有明确状态。

报告按题、图型与复杂度展示客观通过率、语义缺陷、几何缺陷、完整成本和人评。跨工具只汇总预声明共同子集；同时展示全任务覆盖。文件与图片按 digest 链接，人工应能从同一行打开产物和错误证据。

## 实现范围与验证要求

第一实现切片只增加 benchmark 的 metric registry、v2 记录/聚合、独立语义与可见几何适配、消融入口、人评导入和静态报告；不改 renderer、validator、schema-v1、安装行为或现有 v1 分数。建议放置于 `benchmarks/diagram-quality/`，复用现有模块；确需共享接口时再划清 ownership，不以复制整个旧 harness 开始。

Node.js 和现有 JSON/JSONL 是默认实现方式。具体文件拆分、简单报告布局和无关性能小优化由实现者决定。第三方 adapter 可以渐进加入，但未完成某 adapter 不得生成虚假的完整比较。

有意义的验收包括：已知漏节点/错边/信息删除被拒绝；合法等价布局通过；隐藏元素不能冒充可见事实；意外重叠与父子包含被区别；完全相同输入可重现客观结果；human 缺失/补评都不改变自动 score；产物 hash 变化使旧人评失效；失败和超时保留在分母；usage 不重复加缓存/推理字段；混合版本报告拒绝；v1 历史口径保持。

先完成计分器的受控干预校准，再运行低成本开发集与字段消融；真实对照先挑两个高区分度任务做 end-to-end smoke，然后确认所需 provider、可运行工具版本与预算后扩展试点。首轮试点默认无模型消费或人工评分自动启动；本次只有无需模型的研究探针已运行。
