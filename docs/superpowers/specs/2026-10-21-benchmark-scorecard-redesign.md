# 绘图 benchmark：先有成绩单，再有实现

状态：用户已批准并实现，试点评分版本 `diagram-quality-score-v1-pilot-20261021`；权重与锚点已冻结。本文取代旧设计中“细微几何问题即可把整题清零”“不提供综合分”的产品决策。已有独立验收、真实 usage、可复查产物等基础能力继续复用。

## 用户的要求与本次纠偏

用户首先要看懂结果：一行 0–100 总分、一组同尺度分项、可画表格和柱状图的数字。主观评价也必须是评分。主页面中文；测试数量、JSON 回执、文献和实现细节不占据成绩中心。

既有实现把工程测试通过与任务成绩混在展示中心，把很小的字号偏差与内容完全错误一同处理成整题失败；人工虽然已有数值输入，却没有进入可理解的汇总。此次重新设计评分产品，而非给旧 HTML 换皮。

## 成绩单契约

同一版本、轨道、任务集、模型/Agent 配置与预算下，每个参评方法最终有一行：

`方法 | 内容正确 | 布局可读 | 速度效率 | 成本效率 | 人工观感 | 总分`

所有分项和总分均为 0–100、越高越好，显示一位小数，先用未舍入值求总分。首屏是总分柱状图和这张表。原始秒数、tokens、USD、任务成功率及样本数紧随其后；逐题产物、扣分依据与评分规则可展开。CSV/JSON 与 PNG 使用完全相同的数据。

### 固定的试点权重（项目政策，不是论文证明的最优值）

| 分项 | 权重 | 面向读者的问题 |
| --- | ---: | --- |
| 内容正确 C | 45% | 节点、方向、关系和条件画对了吗？ |
| 布局可读 L | 20% | 必需内容是否重叠、被截断、太小或难以追踪？ |
| 速度效率 T | 10% | 正确交付需要多长时间？ |
| 成本效率 K | 10% | 正确交付消耗多少实际模型费用？ |
| 人工观感 H | 15% | 人是否觉得清楚、协调、美观、愿意采用？ |

综合分：`0.45 C + 0.20 L + 0.10 T + 0.10 K + 0.15 H`。

权重是“我们重视什么”的公开政策。首版保留权重敏感性导出，人评一致性仍待真实实验；可以发布标明试验版的数值，不再因为“未校准”禁止展示所有数值。改变权重、阈值或任务集必须产生新评分版本；不能为让 Archify 胜出而调参。

## 逐题分数如何产生

### 内容正确

节点、关系分别一对一匹配，保留 precision/recall/F1；必需名称、方向和条件必须匹配最终可见内容。采用 `C_i = 100 × (0.4 × 节点 F1 + 0.6 × 有向关系 F1)`；节点权重 40%、关系权重 60% 是实现者建议。条件/名称已在匹配中考察，不再把同一 label 的正确性重复加权。没有关系的题预声明使用节点分，不依参评结果改变规则。更复杂的类型事实须有类型专属打分器，才能进入正式计分任务集。

内容缺陷可以有部分分，而不是一个错字清空整题。源完全无效、没有交付或不满足可编辑交付要求的模型失败是该题 0 分。核心必需事实完全未命中（C_i=0）时，各分项贡献与整题分数均为 0，避免“空图布局完美”。

### 布局可读

用四类等权、连续、可解释的子分：遮挡/重叠、裁切/容纳、有效字号、路径可追踪性，各占布局分 25%。评价对象是题目预声明的必需节点、标签和关系；可选图例与装饰不增加分母。丢掉必需内容的相应对象得 0，不能通过删节点或添加大量小装饰改善比例。合法父子包含、端口接触不当作意外碰撞。

每类用必需对象的合格程度平均，而非无限累计缺陷对数。遮挡按该对象被其他对象覆盖面积的并集占比，裁切按超出展示/所属范围的面积占比；重叠面积不重复计数。字号按 `min(1, 有效字号/参考字号)` 给连续分，零可见面积得 0。路径按未侵入无关必需节点的长度占比，必要端点接触免责。混合节点、文字或边时先在同类对象内平均，再对非空对象类别等权；不由生成者新增对象改变类别权重。未命中必需对象按对应类别的 0 分处理。

例如 11.9px 对 12px 参考值约为 99.2% 的字号子分；它不会再让内容正确、可编辑的整张图直接变成 0。实际阈值与面积容差仍写入评分版本，原始观测可复算。几何是可读性代理，人评负责其没有覆盖的视觉偏好。

### 时间与费用

每个任务预先固定目标值 good 和预算上限 bad，按难度层校准并冻结；使用 `E(x) = 100 × clamp((bad - x)/(bad - good), 0, 1)`，good < bad。达到或优于目标得 100，达到上限得 0，中间线性换算。不得根据这次参评方法中的最好/最差值重新缩放。

T 使用最终交付候选的提交时间，起点为真实任务 dispatch，包含生成、工具等待和修复；离线评分器耗时不加到生成时间。最终产物仍须内容完整正确且可编辑。首次正确草稿时间单列为诊断项，不作为主分，以免历史草稿缺少独立验收证据就让正常多轮修图无法计分。K 使用完整任务 invocation 的实际费用，包含提示、工具结果、推理、缓存与失败重试，采用固定定价快照；评估器/人工费用另报。终端也报完整模型 tokens、秒数和费用，不能只给换算后的分数。

没有内容完整正确且可编辑的交付，T_i/K_i 为 0；错误图不能靠快速省钱拿效率奖励。对最终选定产物按同一候选验收语义，不能提交正确草稿领取效率分、最后交付错误图。已知时间/费用预算违规的运行也不得获得效率奖励。没有完整实际 usage 是测量不完整，不把其费用补成 0。

### 人工观感

人只需为阅读追踪、层级分组、排版平衡、风格一致性、整体审美各选 1–5 分，评论选填，不能要求写评语才能提交。`H_i = 25 × (五项平均分 - 1)`；1/3/5 分对应 0/50/100。主观分确实进入综合分。

先对每位评审的五项求平均，再对同一题的评审等权平均；每题至少两位独立评审用于综合榜。模型、工具、成本、自动分隐藏，随机展示顺序；评审数不同不能让某题在总分中更重。工程演示可使用显著标注的虚构评分，但不得混入真实榜单。独立语义复核可另设选项，不强迫人工撰写文本或把语义判断混进审美分。

## 人评 optional 与单一总分如何兼容

明确两个固定轨道，每个轨道只有一个主分数，不在同一榜单混排：

- **自动分**：用于无人的 autodev/autoresearch，`A = (45C + 20L + 10T + 10K)/85`，范围 0–100。
- **综合分**：用于含人评的比较，`S = 0.85A + 0.15H`，范围 0–100。

不做人评就完整输出自动分，不伪造 H，也不把缺失 H 补 0。对外的“含人评综合分”需要同一预声明任务集上人评完整；缺评显示“待完成，已有自动分”，不得把另一组权重得到的自动分冒充综合分。没有产物的已知任务失败，各分项为 0，不要求人给空白页审美评分。所有已交付待评产物都必须进入相同的人评任务集，不能只评最好看的成功子集。

## 汇总、失败与完整性

先算每个任务重复的五个数，再在该任务内对重复等权平均，再对预声明任务等权平均。最后使用固定权重求总分。因此上述表中五个平均分按权重相加就能复算总分。

原生五种图形、难度分层与扩展题的选题原则可以沿用，但评分集只接纳有完整打分器且参评方法共同支持的预声明任务。实验启动前固定，不根据分数事后删题。扩展集单独展示；未来纳入主分会升级版本。

模型无产物、超时、已知交付失败贡献 0，保留在任务分母。评分器故障、身份混用、缺失真实 usage 或无法测量的类型是“实验未完成”，不能冒充模型失败凑一个 0，也不能删除后抬高总分。预检应在模型消费前暴露这些缺口。完整跑完后必须输出数值主成绩，不应让所有正常运行都停在 unverified。

官方计分与优化资格分开：合法试验版仍可输出数值；缺陷类型、原始分量和版本均可复查。autodev 优化自动分，必需安全/交付/信息保留护栏另外固定；优化候选必须保留基线已正确的全部必需事实，不允许靠删除事实或严重语义退化换收益。单题小字号变化造成布局分小幅变化，不使整批实验突然 invalid。

## 对比结果、消融与呈现

比较对象仍可包括同一模型的 Archify/Mermaid/SVG/HTML，以及已核实的同类工具/论文方法；完成相关计分适配器后才跑相应共同任务集。工具比较与模型比较分组，图题明确模型、Agent、任务数、轨道及版本。主图是从 0 起的总分柱状图，分项用同为 0–100 的表或分面柱状图；不以蜘蛛图或工程测试通过数量作为主要成绩。

新消融先问“这个分项能识别什么变化”：删事实应降 C、反转关系应降关系得分、减少重叠应升 L、只换颜色不应改 C/T/K、已正确内容更快/更省应升 T/K、补人评只改变综合分。每个分项移除后的排序变化、冻结权重附近扰动后的排序稳定性都可见。区分计分器敏感性与真正关闭工具组件的机制实验。

中文报告按三层组织：第一层看总分和差距，第二层看五项与原始秒/token/USD，第三层点开看图、具体扣分、原始证据与引用。终端输出同样先给一行分数。导出 CSV/JSON/PNG；一个正常命令跑完即得到成绩，不要求 reviewer 手工组装回执。

PPT 重写为约 8–10 页主线加方法附录：要回答的问题、成绩单、五项权重、真实扣分样例、人工评分、时间/成本、任务与公平性、运行/复现。每页一个主要结论，优先图、数、表；文献、精细公式和内部轨道放附录。没有真实完整对比前，示例分数必须显著标“示意，非实测”，不能制造 Archify 优势。

## 参考关系与实现边界

- [SWE-bench 官方榜单](https://www.swebench.com/)：借鉴主成绩、可比较配置与细节下钻；其 % Resolved 是成功任务比例，并非本设计加权分的论文依据。
- [DiagramEval](https://arxiv.org/html/2510.25761v1)：借鉴图结构中节点/关系分开的解释；这里采用必需有向直接关系，不等同其路径对齐实现。
- [ChartMimic §2.4](https://arxiv.org/html/2406.09961v2#S2.SS4)：借鉴产物分项量化与人工相关性检验；不把复刻参考颜色当通用审美。
